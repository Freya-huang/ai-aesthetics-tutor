# AI美学导师智能体 - 产品需求文档（PRD）

## Overview
- **Summary**: 构建AI美学导师智能体系统，一期包含两个独立智能体（作品诊断智能体、论文解读智能体）和一个共享RAG知识库，通过统一网页入口提供服务。作品诊断智能体接收图片及创作意图，输出基于画面证据的教学反馈；论文解读智能体接收PDF文档，输出带页码依据的观点梳理和概念史关联。
- **Purpose**: 为美学学习者提供即时、有据可依的教学反馈和文献解读支持，帮助学生学会观察画面、理解论证，建立美学知识与创作实践的连接。
- **Target Users**: 美学专业学生、艺术学习者、视觉设计从业者、美学研究者。

## Goals
- 构建作品诊断智能体：基于视觉观察和知识库检索，提供结构化的教学反馈
- 构建论文解读智能体：解析PDF内容（文字+图片），提供带页码依据的观点梳理
- 搭建共享RAG知识库：支持美学知识检索、来源展示、概念关联
- 提供统一网页入口：支持任务选择、文件上传、结果展示、知识点追问
- 确保输出证据可追溯：所有结论均标注来源（画面证据/页码/知识库条目）

## Non-Goals (Out of Scope)
- 练习题库系统
- 学生成长档案
- 用户账户系统（登录、注册、个人中心）
- 正式生产环境部署
- 多轮长对话记忆（只支持单轮追问）
- 识别人物身份或肖像
- 审美价值裁决（不评判"好不好看"）
- 虚构理论关联或冒充作者原话

## Background & Context
- 现有资源：包含AIA（人工智能美学）、THE（美学理论）、VIS（视觉美学）三大类共20份知识库文档
- 技术选型约束：需要支持多模态（图片+文本）处理、PDF解析、RAG检索、Web界面
- 教学原则：先观察后评价，所有结论必须有证据支撑，知识来源可追溯
- 两个智能体职责隔离：不共享对话历史，仅共享经过审核的知识库

## Functional Requirements

### 作品诊断智能体
- **FR-1**: 支持上传JPG、PNG、WebP格式图片，检查格式、大小和清晰度
- **FR-2**: 接收用户输入：作品类型、使用场景、表达意图、本轮关注点
- **FR-3**: 视觉模型生成纯"可观察记录"，不包含价值判断
- **FR-4**: 基于观察记录检索知识库1-3条相关知识（构图、色彩、光影、媒介、作品语境）
- **FR-5**: 按照指定模板生成教学反馈，标注使用的知识条目
- **FR-6**: 页面展示来源卡片和可继续追问的知识点（最多3个）
- **FR-7**: 支持点击知识点进行追问，将"条目名称+当前任务摘要"作为新问题

### 论文解读智能体
- **FR-8**: 支持上传PDF文档，解析文字并保留页码和章节顺序
- **FR-9**: 识别并提取论文中的图片，使用视觉模型生成图片观察记录
- **FR-10**: 提炼研究问题、核心观点、关键概念和论证结构
- **FR-11**: 基于关键概念检索共享知识库（关键概念、理论家、经典问题、相关研究）
- **FR-12**: 仅在证据充分时建立经典问题或概念史关联，禁止虚构关联
- **FR-13**: 按照指定模板输出解读报告，标注PDF页码依据
- **FR-14**: 展示RAG来源卡片，支持知识点追问

### 共享RAG知识库
- **FR-15**: 导入现有知识库文档（AIA/THE/VIS三大类）
- **FR-16**: 支持文档向量化和语义检索
- **FR-17**: 检索结果返回知识条目内容、来源标识、分类标签
- **FR-18**: 确保知识库内容经过审核，不返回未入库内容

### 统一网页入口
- **FR-19**: 首页提供任务选择（作品诊断/论文解读）
- **FR-20**: 作品诊断页面：图片上传区、创作意图表单、结果展示区
- **FR-21**: 论文解读页面：PDF上传区、阅读目的表单、结果展示区
- **FR-22**: 结果展示区：按模板输出结构化内容、来源卡片、可点击知识点
- **FR-23**: 知识点追问交互：点击后发送新请求，展示追加反馈

## Non-Functional Requirements
- **NFR-1**: 图片/PDF上传后30秒内返回初步反馈
- **NFR-2**: 所有来源引用必须准确可查，不允许虚构来源
- **NFR-3**: 界面清晰易用，符合教学场景的阅读体验
- **NFR-4**: 两个智能体的对话上下文完全隔离，互不干扰
- **NFR-5**: 支持中文输入输出，专业术语准确规范
- **NFR-6**: 图片/PDF文件本地处理，不上传至第三方服务（除模型API外）

## Constraints
- **Technical**: 
  - 优先使用Python生态（FastAPI/LangChain等）
  - 支持本地运行，可配置LLM和视觉模型API
  - 前端使用现代Web框架（React/Vue等）
- **Business**: 一期为原型验证阶段，不做生产级部署
- **Dependencies**: 
  - LLM API（文本生成）
  - 视觉模型API（图片理解）
  - PDF解析库
  - 向量数据库/向量检索引擎

## Assumptions
- 用户已有可用的LLM API和视觉模型API密钥
- 知识库文档格式统一，可被有效解析和分块
- 一期仅支持单用户本地使用，无需并发处理
- 知识点追问为单轮追问，不保留多轮对话历史

## Acceptance Criteria

### AC-1: 作品诊断图片上传与验证
- **Given**: 用户进入作品诊断页面
- **When**: 上传不符合格式的文件或超过大小限制的图片
- **Then**: 系统显示明确的错误提示，拒绝处理
- **Verification**: `programmatic`

### AC-2: 作品诊断可观察记录生成
- **Given**: 用户上传有效图片并填写创作意图
- **When**: 视觉模型分析图片
- **Then**: 输出仅包含可观察的画面元素和视觉关系，不包含"好看/不好看"等价值判断
- **Verification**: `human-judgment`
- **Notes**: 需检查是否有主观评价词汇

### AC-3: 作品诊断知识检索与反馈生成
- **Given**: 视觉观察记录已生成
- **When**: 检索知识库并生成教学反馈
- **Then**: 反馈按指定模板输出，每个知识引用标注来源，推荐知识点不超过3个
- **Verification**: `human-judgment`

### AC-4: 作品诊断输出模板完整性
- **Given**: 作品诊断完成
- **When**: 展示诊断报告
- **Then**: 报告包含所有指定板块：创作目标、视觉现象、值得保留、重点学习、美学知识、多元理解、修改任务、反思问题、使用边界、知识来源
- **Verification**: `programmatic`

### AC-5: PDF解析与页码保留
- **Given**: 用户上传有效PDF文档
- **When**: 系统解析PDF
- **Then**: 文字内容保留原始页码标记和章节结构
- **Verification**: `programmatic`

### AC-6: 论文观点提炼与页码依据
- **Given**: PDF解析完成
- **When**: 生成解读报告
- **Then**: 每个核心观点都标注对应的PDF页码，不出现无页码依据的概括
- **Verification**: `human-judgment`

### AC-7: 论文解读输出模板完整性
- **Given**: 论文解读完成
- **When**: 展示解读报告
- **Then**: 报告包含所有指定板块：文献信息、核心观点、研究问题、关键概念、论证结构、经典问题关联、图片案例、贡献局限、建议阅读、来源边界
- **Verification**: `programmatic`

### AC-8: 知识库检索准确性
- **Given**: 知识库已完成导入和向量化
- **When**: 使用明确的美学概念进行检索
- **Then**: 返回相关的知识条目，不返回无关内容
- **Verification**: `human-judgment`

### AC-9: 来源展示与禁止虚构
- **Given**: 任一智能体生成报告
- **When**: 展示知识来源
- **Then**: 所有展示的来源都是知识库中实际存在的条目，不显示虚构来源
- **Verification**: `programmatic`

### AC-10: 知识点追问功能
- **Given**: 报告展示可点击的知识点
- **When**: 用户点击某个知识点
- **Then**: 系统以"知识点名称+当前任务摘要"作为问题发送给对应智能体，展示追加反馈
- **Verification**: `programmatic`

### AC-11: 智能体上下文隔离
- **Given**: 用户先后使用作品诊断和论文解读功能
- **When**: 在两个功能间切换
- **Then**: 两个智能体的对话历史互不影响，不会出现论文内容出现在图片诊断中或反之
- **Verification**: `programmatic`

### AC-12: 统一网页入口流程
- **Given**: 用户访问首页
- **When**: 选择任务类型并完成操作
- **Then**: 按照流程图完成从任务选择到结果展示的完整流程，页面导航顺畅
- **Verification**: `human-judgment`
