# 定制火车票生成器 - Product Requirement Document

## Overview
- **Summary**: 一个基于用户提供的空白火车票模板的在线定制工具，允许用户输入完整的车票信息（出发站、到达站、日期、车次、乘客、座位、票价等），系统自动在模板上生成精美的定制火车票图片，并在右下角生成二维码，扫码后可查看完整的车票文本信息。
- **Purpose**: 满足用户制作个性化、纪念意义的定制火车票需求，可用于生日礼物、旅行纪念、创意设计等场景。
- **Target Users**: 想要制作创意纪念火车票的普通用户、情侣、旅行者、设计师等。

## Goals
- 提供直观的表单界面让用户输入火车票信息
- 基于用户提供的浅蓝色CRH动车组空白模板，精准定位文字位置生成仿真火车票
- 生成包含完整车票信息的二维码，扫码后显示纯文本车票详情
- 支持生成的火车票图片下载保存
- 作为独立小工具页面，不集成到现有导航菜单

## Non-Goals (Out of Scope)
- 不与真实12306系统对接，不生成真实可用的车票
- 不支持模板上传和自定义模板功能（固定使用用户提供的模板）
- 不添加社交分享功能（仅支持图片下载）
- 不添加历史记录保存功能（纯前端一次性生成）
- 不集成到现有美学agent项目的主导航中，作为独立路由页面存在

## Background & Context
- 现有项目：基于React+TypeScript+Vite的前端，FastAPI后端
- 用户已提供空白火车票模板：浅蓝色背景，CRH动车组水印，包含"站→站"、"年月日:开"、"车号"、"¥.元"、"仅供报销使用"、二维码占位框、底部标语等元素
- 二维码要求：扫码后显示纯文本火车信息
- 技术选型：使用前端Canvas或HTML+CSS方式绘制，二维码使用qrcode库纯前端生成
- 项目作为独立小工具，可通过直接访问路由URL使用

## Functional Requirements
- **FR-1**: 用户可以在表单中输入以下车票字段：
  - 出发站、到达站
  - 出发日期（年、月、日）、发车时间（时:分）
  - 车次号
  - 乘客姓名
  - 席别（如：二等座、一等座、商务座、硬座、硬卧等）
  - 座位号（如：05车12A号）
  - 票价（元）
  - 检票口（可选）
  - 身份证号（自动脱敏显示，如：110***********1234）
- **FR-2**: 用户输入信息时，实时预览生成的火车票效果
- **FR-3**: 系统在模板右下角方框位置生成二维码，二维码编码内容为格式化的纯文本车票信息
- **FR-4**: 用户可以下载生成的火车票为PNG图片
- **FR-5**: 提供表单重置功能，清空所有输入
- **FR-6**: 二维码扫码后显示结构化纯文本，包含所有车票信息

## Non-Functional Requirements
- **NFR-1**: 响应速度：输入后预览更新延迟<200ms
- **NFR-2**: 图片生成质量：生成的图片分辨率足够清晰，适合打印（至少2x分辨率）
- **NFR-3**: 兼容性：支持主流现代浏览器（Chrome、Safari、Firefox、Edge）
- **NFR-4**: 易用性：表单字段有合理的默认值和示例提示
- **NFR-5**: 纯前端实现，无需后端API支持（除了现有静态资源服务）

## Constraints
- **Technical**: 
  - 前端必须使用项目现有技术栈：React 18 + TypeScript + Vite
  - 二维码生成使用纯前端JavaScript库（qrcode或qrcode.react）
  - 图片生成使用html2canvas或Canvas API
  - 必须使用用户提供的固定模板图片
- **Business**: 仅供娱乐/纪念使用，需在页面上标注"仅供娱乐，非真实车票"提示
- **Dependencies**: 需要安装qrcode和html2canvas（或类似）npm包

## Assumptions
- 用户提供的模板图片尺寸固定，文字位置可以通过CSS绝对定位精准放置
- 二维码生成使用纯前端方案，无需后端服务
- 所有文字绘制在前端完成，不需要后端图像处理
- 独立页面可通过 `/ticket` 路由直接访问

## Acceptance Criteria

### AC-1: 表单输入完整字段
- **Given**: 用户访问火车票生成页面
- **When**: 查看表单区域
- **Then**: 显示所有必要的输入字段：出发站、到达站、日期（年月日）、时间（时分）、车次、姓名、席别、座位号、票价、检票口、身份证号，并有合理默认值
- **Verification**: `human-judgment`

### AC-2: 实时预览
- **Given**: 用户已打开页面并看到初始预览
- **When**: 修改任意表单字段
- **Then**: 火车票预览区域实时更新对应文字内容，响应迅速
- **Verification**: `human-judgment`

### AC-3: 文字位置准确
- **Given**: 用户填写了所有字段
- **When**: 查看预览火车票
- **Then**: 出发站/到达站位于顶部"站→站"位置，日期时间在"年月日:开"位置，车次在"车号"位置，票价在"¥.元"位置，与模板占位符对齐
- **Verification**: `human-judgment`

### AC-4: 二维码生成
- **Given**: 用户填写了车票信息
- **When**: 查看预览火车票右下角
- **Then**: 方框内显示可扫描的二维码，二维码清晰可识别
- **Verification**: `programmatic`
- **Notes**: 可通过二维码解码验证内容正确性

### AC-5: 二维码内容正确
- **Given**: 已生成二维码
- **When**: 使用手机扫码二维码
- **Then**: 显示纯文本，包含格式化的所有车票信息（车次、出发到达站、日期时间、乘客、座位、票价等）
- **Verification**: `human-judgment`

### AC-6: 图片下载
- **Given**: 用户对预览效果满意
- **When**: 点击"下载车票"按钮
- **Then**: 浏览器下载PNG格式的火车票图片，图片内容与预览一致
- **Verification**: `programmatic`

### AC-7: 重置功能
- **Given**: 用户已填写了一些内容
- **When**: 点击"重置"按钮
- **Then**: 所有表单字段恢复默认值，预览恢复初始状态
- **Verification**: `programmatic`

### AC-8: 页面独立访问
- **Given**: 项目已部署
- **When**: 直接访问 `/ticket` 路由
- **Then**: 可以正常打开火车票生成器页面，不影响现有其他页面功能
- **Verification**: `programmatic`

### AC-9: 免责声明
- **Given**: 用户打开页面
- **When**: 查看页面
- **Then**: 页面明显位置显示"仅供娱乐纪念，非真实有效车票"提示文字
- **Verification**: `human-judgment`
